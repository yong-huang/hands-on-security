# 05 · 数据包构造与嗅探工具：ARP 扫描、ping sweep 与抓包过滤

> ping、nmap（端口扫描器）这类现成工具只能用它给的功能；scapy（Python 数据包工具箱）
> 把每个协议层变成可构造、可发送、可捕获、可解析的对象。本实验用约 240 行
> 实现 ARP 扫描（按 IP 问出对方网卡地址的协议）、ICMP 扫描（ping 背后的
> 控制报文协议）与「边抓边发」演示。发送原始包与抓包需要 root，只打本机网段。

## Background

在 scapy 之前，自己「造一个包」的门槛极高：要么用 C 写原始套接字、手工拼
每一层头部和校验和；要么用 ping 这类成品工具，只能调它开放的几个参数。

两种方式都撞墙：教学上，教科书里的协议字段图没有「活的」实验——想亲手改
一个字段看看收端如何反应，做不了；工程上，写协议测试用例、复现诡异的网络
问题，都需要精确控制每个字节。

scapy 把数据包变成 Python 对象，分层、字段、类型全都可编程：造包、发包、
抓包、拆包四件事收进一套 API，协议从此可以在交互式解释器里直接做实验。

## What

一句话定义：数据包构造与嗅探工具是**用可编程的包对象完成构造、发送、
捕获与解析四件事的工具**。

心智模型：协议分层像套娃——帧里装 IP 包，IP 里装 TCP/ICMP；scapy 的
`/` 运算符就是「套信封」：`Ether()/IP()/ICMP()`。失效边界：构造只是内存里
的字段树，「出门」要内核和网卡放行（原始套接字是特权资源）。

四个动作对应四个子命令，权限各不相同：

| 动作 | scapy 入口 | 本实验命令 | 权限 |
|:---|:---|:---|:---|
| 构造 + 序列化（字段树 → 二进制字节流） | `Ether()/IP()/...`、`bytes()` | `craft` | 免 root |
| 发送并收应答 | `sr()`、`srp()` | `arp-scan`、`ping-sweep` | root |
| 捕获 + 过滤 | `AsyncSniffer(filter=...)` | `sniff` | root |
| 反解析（二进制 → 字段树） | `Ether(raw)` | craft 内置核对 | 免 root |

## When to Use

典型场景：协议学习（把教科书字段图跑成实包，眼见为实）；安全测试（ARP
扫描发现同网段资产、构造畸形包验证解析器）；网络排障（抓包定位「谁没应答」，
比 ping 的输出信息多一个量级）。

何时不用：只测连通性，系统 `ping` 更快；长期抓包，tcpdump（命令行抓包工具）
/Wireshark（图形化抓包分析器）更省事；未授权网段不扫描、不抓包——ARP 扫描
相当于挨家挨户敲门，但一次广播问遍整栋楼，还会在被扫设备上留痕。

| 方案 | 机制 | 什么时候选它 |
|:---|:---|:---|
| scapy（本实验） | 可编程构造 / 发送 / 抓 / 拆 | 要精确控制字节、写自动化 |
| tcpdump / Wireshark | 只抓不造，筛选强大 | 以抓包分析为主 |
| ping / nmap | 成品工具，参数有限 | 常规连通性与端口检查 |

## Quick Start

前置：`pip3 install scapy`；发送与抓包需要 root（sudo 会提示输入登录密码）。

```bash
cd network/05_packet_tool
sudo ./packet_tool.sh            # apply → observe → clean 一条龙（约 8 秒）
sudo ./packet_tool.sh observe    # 只跑四步演示；无 sudo 时自动跳过特权步骤
./packet_tool.sh                 # 免 root：只做构造演示并提示如何补全
```

observe 阶段的真实输出（节选）：

```text
... # apply 自检段（python3 路径、出口、权限提示均正常）与 ① 构造演示（约百行）省略
=====> [observe] ② ARP 扫描本网段（需要 root）
[*] ARP 扫描 192.168.50.0/24（广播 who-has × 254，收集 2.0s）
[*] 本机 MAC ce:c4:8c:e7:33:99（自己不会回应自己的广播）
[ARP] 192.168.50.1     a0:36:bc:70:b4:10  ← 网关
... # 其余 8 台应答省略
[=] 应答 9 台，耗时 2.24s
  ✅ ARP 扫描列出网关与本机 MAC

=====> [observe] ③ ICMP 扫描本网段（需要 root）
[*] ICMP 扫描 192.168.50.0/24（echo-request × 254，超时 1.0s）
... # 前 4 台应答省略
[PING] 192.168.50.97    0.000s  ← 本机
[=] 可达 5 台，耗时 1.36s
  ✅ ping sweep 列出在线主机（回包带 ← 网关 / ← 本机 标记）

=====> [observe] ④ 抓包：边抓边发，捕获自己发的 ping（需要 root）
[*] 抓包 lo0 filter=icmp：边抓边发 6 次 ping 127.0.0.1（预计 12 个 ICMP 包，目标 12 个）
[SNIFF] #01 Loopback / IP / ICMP 127.0.0.1 > 127.0.0.1 echo-request 0
... # #02–#09 共 8 个省略
[SNIFF] #10 Loopback / IP / ICMP 127.0.0.1 > 127.0.0.1 echo-reply 0
```

诚实预期（新手第一个失败点）：不加 sudo 时 ②③④ 打印「⏭ 跳过：需要 root」
并继续收尾——这是预期行为。另一处「看起来失败」：抓包目标 12 个、实测 10 个，
首帧可能赶在抓包器就绪前发出，阈值 ≥10 正是为容纳这个启动竞态。

## How It Works

![一次 ping 的生命：构造、发送、应答与抓包](images/packet_tool.svg)

> 怎么看：工具把字段树序列化成二进制交给内核（本地工具 → 内核与网卡），
> 对端回 echo-reply；抓包器经特权通道拿到同一帧的副本并打印摘要。

> 🌐 **交互版**：本地打开 [`images/packet_tool.html`](images/packet_tool.html)。

**构造 ≠ 发送**：`craft` 里三个包都只活在内存里。序列化时才定型长度、算
校验和——下面这段真实输出就是「字节流」与「反解析」的对照：

```text
[*] 序列化：42 字节（网卡实发时会补到 60 字节）
0000  FF FF FF FF FF FF CE C4 8C E7 33 99 08 06 00 01  ..........3.....
0010  08 00 06 04 00 01 CE C4                          ........
[*] 反解析核对：op=who-has、pdst=192.168.50.1 ✓
```

**ARP 扫描为什么可靠**：ARP 工作在二层（以太网），「谁是 192.168.50.1」的
广播由设备网卡直接应答，不经过 IP 层，防火墙通常管不到。所以「ARP 有回、
ping 不回」的设备很常见——实测同一网段 ARP 9 台、ICMP 只 5 台。

**抓包为什么要 root**：macOS 的抓包通道是 `/dev/bpf*`（BPF，Berkeley Packet
Filter：内核里按表达式筛帧的抓包机制）——特权设备，能看见流过网卡的所有帧。
实验「边抓边发」（lo0 回环网卡，流量不出机器），闭环最确定。

**混杂模式的小坑**：scapy 默认请求网卡进混杂模式（收所有帧），macOS Wi-Fi
驱动不支持（报 ENOTSUP，即「操作不支持」）；工具显式 `promisc=False`，只收自己的流量。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **不加 sudo 只看到①**：②③④ 需要原始套接字与 /dev/bpf 权限——用
  `sudo ./packet_tool.sh` 重跑即可。
- **ENOTSUP: Cannot set promiscuous mode**：Wi-Fi 驱动不支持混杂模式；
  工具已内置 `promisc=False`，自己写脚本时记得同样处理。
- **ping sweep 里网关没出现**：部分路由器不开 ICMP 应答；ARP 扫描能补上
  它（本机实测网关只答 ARP 不答 ping）。
- **ARP 扫到的台数每次不同**：设备休眠、离线的正常波动；多跑两次取并集。

深入问答：

- **Q: 能伪造源 IP 吗？** A: scapy 允许把 IP.src 写成任意值（教学常用来
  理解伪造），但应答会送往伪造的地址、你收不到——只是单向投递。
- **Q: 为什么用回环演示抓包？** A: 确定性：不依赖外部网络，发 6 次固定
  产生 12 帧（启动竞态下实际捕获 10 帧，见 Quick Start 诚实预期）；抓 en0
  会混入其他设备流量，演示不稳定。
- **Q: macOS 和 Linux 的权限差别？** A: 都要 root：macOS 经 /dev/bpf，
  Linux 用 AF_PACKET 套接字（Linux 收发链路层帧的接口，作用对应 /dev/bpf）。
  没有 sudo 可在 Docker linux 容器里跑（ARP 只覆盖容器网桥）。
- **Q: 这些技术能用来攻击吗？** A: 反过来看——ARP 扫描与抓包是排查自家
  网络的基本功；技术中性，边界是「只碰本机与授权网段」。
