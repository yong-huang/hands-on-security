# 18 · 命令注入与综合通关：黑名单三连败与一份渗透报告

> 命令注入 = 把「命令」混进「参数」里。本实验先用 payload（攻击载荷：塞
> 进参数、到目标机上执行的注入字符串）速查表把四式
> （分号 / 管道 / 反引号 / `$()`）与空格绕过（`${IFS}`）讲透，再对 DVWA（故意布满漏洞
> 的本地靶站）三档实战：low 分号直取 root；medium 删了 `&&` 和 `;`，用 `|` 照走；
> high 连「管道加空格」都删，用 `|` 后不加空格的变体照样过。最后核验
> 《DVWA 渗透测试报告.md》——6 类漏洞的实测档案。只打本地靶场。

## Background

Web 应用经常需要调用系统命令（ping 诊断、图片处理、压缩打包）。把用户
输入粘进命令串的那一秒，注入就成立了——shell 不区分参数和命令，只认
分隔符：分号接着说、管道递输出、反引号与 `$()` 先算再嵌。和 SQL 注入
同源：**输入进了代码语境**，就获得了代码的威力。

危害天花板也最高：SQL 注入是「替你查数据」，命令注入是「替你执行操作」
——本实验里那只手还是 root。

## What

一句话定义：**命令注入是把攻击者构造的额外命令，搭着正常参数的便车
送进系统 shell 执行**。

心智模型：shell 命令像一句口述指令——你递纸条让前台「给 127.0.0.1 送
4 个包裹」，纸条被多加了一句「顺便把钥匙也给我」，前台照单全读。失效
边界：注入的成立**不依赖回显**——没有回显时，结果可以外带（HTTP/DNS）
或用时间差异编码；「看不到输出」不等于「没进来」。

四种基础接法（本实验逐式实测）：

| 接法 | 写法 | 语义 |
|:---|:---|:---|
| 分号 | `; cmd` | 串行执行 |
| 管道 | `\| cmd` | 前命令输出灌给 cmd |
| 反引号 | `` `cmd` `` | 命令替换（先算再嵌回） |
| 美元括号 | `$(cmd)` | 命令替换（现代写法） |

## When to Use

典型场景：代码审计中搜「用户输入 + 系统调用」的组合（命令执行函数与
拼接）；渗透中验证诊断类功能（ping/traceroute/转换工具）；给实验 19
的检测造 RCE（Remote Code Execution：远程代码执行）流量样本。

何时不用：未授权目标不碰；确认注入后**证明影响即可**（whoami/id），别
急着写文件或反弹 shell（让受害主机主动连回攻击者、交出命令行）——「能做
的」与「该做的」之间隔着授权范围。

| 做法 | 机制 | 什么时候选它 |
|:---|:---|:---|
| 手工四式（本实验） | payload 速查 + 逐档试 | 看清每层过滤差什么 |
| 自动化压力测试 | 批量变形与编码 | 已确认注入点后的穷举 |
| 代码审计 | 读调用链找拼接点 | 根治、覆盖所有入口 |

Docker 端口代理偶发抖动，工具已内置重试。

## How It Works

![一次命令注入的全程](images/cmd_injection.svg)

> 怎么看：上半段是一次注入的完整往返（payload → 拼接成命令 → 执行 →
> 回显），下半段是「没有回显」时的两条退化路——外带与时间信道。

> 🌐 **交互版**：本地打开 [`images/cmd_injection.html`](images/cmd_injection.html)。

**拼接发生的那一刻**：`shell_exec('ping -c 4 ' . $target)`——字符串拼好
交给 shell，shell 按自己的分词规则再拆一遍：我给你的「参数」里出现它
认的分隔符，就多出一句命令。过滤发生在拼接之前，改变不了拼接的结局。

**三档黑名单的递进与破法**：low 什么都不删（四式随意）；medium 删
`&&` 和 `;`——但 `|`、`&`、反引号、`${IFS}`（代替空格）都还在。

high 把 `||`、`&`、`;`、「管道+空格」、`-`、`$`、括号、反引号全删——可
`|` 后不加空格的变体存活；参数里的空格照用（`|cat /etc/passwd` 可行：
被删的是「`|` 带其后空格」的组合、管道一并消失；命令与参数间空格不受
影响）。**黑名单永远是枚举**，套不完 shell 语法糖。

**没有回显的退化路**：结果不需要原路返回——HTTP/DNS 外带（让服务器主
动连你的接收端，实验 14 的接收端即可复用）；或时间信道（`sleep 5` 与
不 sleep 的响应差当 0·1 比特）。速查表里三条模板都给了。

**报告核验**：《DVWA 渗透测试报告.md》按渗透行业惯例组织：执行摘要 →
6 类漏洞详情（每类含等级实测、复现步骤、证据、影响评级、修复建议）→
风险汇总 → 修复优先级。每节的等级表都标注实测依据，未测项如实标注
「未测」——报告的可信度来自「只写做过的」。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **负例返回空响应而非报错**：ping 的错误输出走 stderr，`shell_exec`
  只收 stdout——把「空」当作「没执行成功」的判据。
- **high 档连 `-` 都删**：想跑带选项的命令（`ls -la`）会被拆——可用无
  选项命令或通配符替代（`cat /etc/passwd` 不需要选项）。
- **管道会吞掉前命令输出**：`…| whoami` 里 whoami 不读 stdin，ping 的
  输出就消失了——回显只剩注入命令自己的输出。
- **本地栈偶发超时**：Docker 端口代理瞬断——工具已内置三次重试。

深入问答：

- **Q: 为什么命令注入是危害天花板？** A: 其它漏洞是「越权读写数据」，
  它是「借服务器的手执行操作」——本实验那只手还是 root；夺权只需再加
  一步提权（见实验 27）。
- **Q: 黑名单为什么必输？** A: shell 的分隔符、替换、变量、编码、通配
  组合无穷，而过滤者只会枚举想到的——白名单（输入格式校验）才是闭集。
- **Q: 报告为什么比「打出 shell」更值钱？** A: 渗透的产出是决策依据
  ——等级、证据、影响、修复建议齐全，修复方才能按优先级动工；实验
  19-21 的检测环节继续接力。
