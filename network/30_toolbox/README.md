# 30 · 个人安全工具箱整合：五合一 sectool 与一键冒烟

> 收官之作：把系列五件工具——01 端口扫描、02 子域枚举、03 目录爆破、
> 07 哈希破解、19 日志审计——收编成一个 `sectool` CLI：五个工具**一行
> 没改**（纯 import 复用），统一输出与退出码（0 无发现 / 1 有发现 /
> 2 参数错 / 3 环境错）。一键冒烟从零起最小靶（临时拉起、只含被测服务的一个
> 本地小环境），五项逐一断言，**连跑 3 次全绿（6 通过 / 0 失败）**——验收：五子命令可用、--help 完整、
> 冒烟三连不红。

## Background

散装工具的痛点很具体：命令记得住、参数记不住；五个脚本五种输出口径；
交付给别人时，「它能干啥」全凭一张嘴。工具化就是把「散装零件」装成
「一条随时能拿起来用的腰带」。

放在系列最后一步还有一个工程逻辑：整合逼你回看每一次接口设计——
参数为什么这么定、输出为什么这么排、退出码为什么这么分。答不上来的
地方，就是你当时没想清楚的地方。

## What

一句话定义：**工具箱 = 把知识封装成可交付、可自证的命令**。

心智模型：工具箱像随身的工具腰带——螺丝刀还是那把螺丝刀（工具零
修改），但拿取、摆放、校验都有了统一方式。

失效边界：工具多一个，维护面就多一块（每个子命令都要有 --help 与
一致的退出码）；不是为了「什么都自己造」——一次性任务直接手敲更划算。

| 子命令 | 来源工具 | 冒烟断言 |
|:---|:---|:---|
| scan-port | 01 端口扫描 | 扫到 :8821 open |
| enum-dns | 02 子域枚举 | 6 个子域 + apex（主域 lab.local 本身）的三类记录 |
| dir-brute | 03 目录爆破 | 命中 /admin.html |
| crack-hash | 07 哈希破解 | 破解 smoke-pass |
| log-audit | 19 日志审计 | 检出爆破来源 IP |

## When to Use

典型场景：日常自用（一条命令完成一类检查）；把检查嵌进脚本或流水线
（退出码就是机器可读的结论）；当作「外设接口设计」的学习样张。

何时不用：一次性任务不值得先造工具；工具化之前先问「它会第二次被
用到吗」——会，才值得封装；不会，手敲完就结束。

| 做法 | 机制 | 什么时候选它 |
|:---|:---|:---|
| 散装脚本 | 各自为政 | 探索期、一次性任务 |
| 本节 sectool | argparse（Python 标准库的命令行参数解析器）子命令 + 统一约定 | 长期自用与交付 |
| 发布为包（pip） | 版本化分发 | 要给团队/社区用时再进化 |

## Quick Start

前置：宿主 python3（requests + dnspython）；dnsmasq（冒烟靶，
`brew install dnsmasq`）；系列 01/02/03/07/19 五个实验目录在场
（sectool 直接 import 它们）。

```bash
cd network/30_toolbox
./toolbox_lab.sh               # --help 展示 → 冒烟三连（约 20 秒）
./toolbox_lab.sh apply         # 只检查依赖与五件工具在场
./toolbox_lab.sh observe       # 只跑帮助展示与三连冒烟（需先 apply）
./toolbox_lab.sh clean         # 清理冒烟夹具
python3 sectool.py scan-port 127.0.0.1 -p 8821   # 单跑任一子命令
```

诚实预期（新手第一个失败点）：① 冒烟会起本地服务（HTTP :8821 与

必须原样在场——sectool 只 import，不复制代码。

## How It Works

![五合一：sectool 从入口到三连全绿](images/toolbox.svg)

> 怎么看：上排主链——sectool 入口分派五子命令 → 五件工具原样复用 →
> 一键冒烟（起最小靶、五项逐一断言）→ 三连全绿；下排是最小靶与夹具：
> 冒烟脚本每次从零拉起，不依赖手搭环境。

> 🌐 **交互版**：本地打开 [`images/toolbox.html`](images/toolbox.html)。

**零修改复用怎么做到的**：`sys.path` 挂上五个工具目录后直接 import；
调用各自核心函数（`scan_one` / `probe_subdomain` / `scan` / `cmd_crack`
/ `apply_rules`）；原格式输出用 `redirect_stdout` 捕获后统一缩进。

**统一约定的三件套**：结果行两空格缩进；末尾一行
`[sectool] <子命令> 完成：发现 N 项 → 退出码 X`；退出码 0/1/2/3 让
「有没有发现」也能被脚本直接消费（像 grep 用退出码承载命中与否；
注意极性相反：grep 命中是 0，sectool 有发现是 1）。

**冒烟为什么值得写**：最小靶从零起（HTTP 目录、lab.local DNS、字典、
认证日志全自动生成）；断言两层——退出码 + 关键输出；`--quiet` 只留
结论行，三连输出才读得下去。冒烟脚本自己也要能「连跑不红」，这是
交付纪律的最后一环。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **导入即执行**：把脚本当模块 import 前先看模块顶层有没有副作用——
  本系列五件工具都克制（逻辑在函数里），才能安全收编。
- **端口被占冒烟红**：HTTP :8821 / DNS :5300 撞车——冒烟自带就绪
  探针（没人应答时明确报「未就绪」），端口被占用时靠断言层兜底判红；
  清掉占用或改端口再跑。
- **bash 全角括号吞变量**：`$HTTP_PORT（` 在旧版 bash 会被算成一个
  变量名报 unbound——紧邻全角字符一律写 `${HTTP_PORT}`。
- **只看输出不看退出码**：grep 到关键字就判绿是假绿——本冒烟两层都
  断言，退出码不对绝不放过。

深入问答：

- **Q: 为什么不把五个工具合成一个长脚本？** A: 子命令就是最小模块化：
  每块独立 --help、独立退出码、独立冒烟——合成长脚本等于把维护面
  揉成一团。
- **Q: sectool 要装进 PATH 吗？** A: 保持仓库内运行（`python3
  sectool.py ...`）避免全局污染；要随身带就自己 `ln -s` 或 alias。
- **Q: 为什么把工具箱放在最后？** A: 学习闭环不在「又学了一个方向」，
  而在「能交付一个东西」——30 课的肌肉记忆，收进一条命令里。
