# 03 · Web 目录爆破器（mini-dirsearch）：字典驱动、软 404 降噪与递归探测

> 网站没写在首页上的路径——后台入口、备份文件、忘了删的测试页——往往是最先
> 被攻破的暴露面。本实验用约 200 行 requests（Python 的 HTTP 客户端库）代码
> 实现目录爆破器，在自建 flask（Python 的轻量 Web 框架）靶站上跑通「字典并发
> 探测 → 状态码白名单 → 软 404（未知路径也返回 200 的假错误页）降噪 → 递归
> 一层」全流程。命令只打本机靶站，勿扫未授权目标。

## Background

没有目录爆破器之前，找隐藏路径靠两种办法：跟着页面链接爬，或凭经验手工试
（直接输 `/admin`、`/backup`）。前者只能到达有链接指向的页面，备份文件、
调试入口这类孤立资源永远进不了视野；后者覆盖太窄，几十个常见名字就没了。

目录爆破把「猜路径」系统化：用一份常见目录与文件名字典（wordlist，每行一个
候选名，如 `admin`、`backup`）批量发请求，按响应差异判断真实存在。但批量
请求马上暴露两个新问题：响应噪音（404/200 混杂）和软 404（未知路径也回
200 的错误页）——本实验逐一解决它们。

## What

一句话定义：目录爆破器是**用一份常见路径字典向目标批量发 HTTP 请求、筛出
「真实存在」路径的工具**。

心智模型：把网站想象成没有楼层指引的大楼，字典是一份机构名册（admin？
backup？login？），按名册逐一敲门——有回音就记下来。但大楼对不存在的门牌
也统一回「查无此人」（软 404）；不先记住「标准查无此人」的长相，就会把
整栋楼的门都当成有人。失效边界：名册里没有的名字，敲多少遍也发现不了。

响应四分类（白名单与丢弃逻辑都围绕它展开）：

| 响应 | 含义 | 处理 |
|:---|:---|:---|
| 301/302 | 目录存在，跳转到带斜杠版本 | 记录，可递归 |
| 200/204 | 资源存在 | 记录（先排除软 404） |
| 403/401 | 存在但禁止访问 | 记录（403 也是有效发现） |
| 404/500 | 不存在或服务出错 | 默认丢弃（白名单之外） |

**递归**：发现目录后，把同一份字典再发到该目录下探测一层子路径。

## When to Use

典型场景：授权渗透的信息收集（定位后台、上传点、备份入口再深挖）；资产自查
（上线前扫自己站点，揪出遗留的 `.bak`、`.git`、测试页）；检测规则演练（给
蓝队检测器制造真实爆破流量）。

何时不用：未授权目标一律不爆破；站点已有 sitemap（站点地图文件）或爬虫结果
时先消费现成清单，缺的部分再补爆破；海量字典的大规模扫描交给 ffuf（主流的
命令行目录爆破工具）等成熟工具——本实验重点是看懂「命中」怎么判出来。

| 方案 | 机制 | 什么时候选它 |
|:---|:---|:---|
| 字典爆破（本实验） | 主动请求候选路径，按响应分类 | 授权范围内系统化补全路径清单 |
| 爬虫抓取 | 沿页面链接遍历 | 快速拿到有链接指向的公开页面 |
| 历史存档（Wayback 等） | 查历史抓取记录里的 URL | 被动、安静地拿旧路径，不产生请求 |

## Quick Start

前置：`pip3 install flask requests`（仓库根 `bash scripts/load_resources.sh`
可一键体检全部依赖）。

```bash
cd network/03_dir_brute
./dir_brute.sh               # apply → observe → clean 一条龙（约 3 秒）
./dir_brute.sh apply         # 只起靶站：127.0.0.1:8010（软 404 陷阱）
./dir_brute.sh observe       # 扫描、断言、降噪对比、递归对照与逐条复核
./dir_brute.sh clean         # 停靶站，端口复原
```

observe 阶段的真实输出（节选，命中顺序随线程调度不同）：

```text
=====> [observe] 字典爆破: http://127.0.0.1:8010（默认字典 + 递归一层）
[*] 目标 http://127.0.0.1:8010  字典 72 条  线程 20  递归 1 层
[*] 软 404 基线：随机路径 → 200，长度 100B（同状态且长度 ±10B 的响应将被丢弃）
[+] /admin                      301 → /admin/
[+] /robots.txt                 200 (51B)
... # 其余 9 条顶层命中省略
[↻] 递归 /admin/（301 判定为目录）
[+] /admin/panel                301 → /admin/panel/
[↻] 递归 /api/（301 判定为目录）
[+] /api/status                 200 (134B)
... # 其余 7 个目录的递归（无新发现）省略
[=] 完成：13 个命中 / 探测 720 个 URL，耗时 0.25s
  ✅ 13 条预置路径全部命中且无多余（11 顶层 + 2 递归）
... # 不加 -r 对照、降噪对比（关闭 72/72 全员「命中」vs 开启 11 条真实）、逐条复核与 DVWA 条件对照四段省略，详见脚本本身
```

爆破器也可独立运行——先 `./dir_brute.sh apply` 起靶站，再
`python3 dir_brute.py http://127.0.0.1:8010 -r`（`-w` 换字典、`--no-filter`
关闭降噪，用完 `./dir_brute.sh clean`）。

诚实预期（新手第一个失败点）：apply 报「靶站 4 秒内未就绪」即 8010 被占用，
`lsof -i :8010` 查占用者或 `LAB_PORT=8011 ./dir_brute.sh` 换端口重跑；不加 `-r`
时只有 11 条命中——递归路径本来就该缺席，不是失败。

## How It Works

![Web 目录爆破流程](images/dir_brute.svg)

> 怎么看：上排爆破器——字典并发探测，响应经「白名单 + 基线窗口」过滤后进命中
> 表，目录命中再触发一层递归；中排靶站以软 404 回应未知路径；下排是误报归宿。

> 🌐 **交互版**：本地打开 [`images/dir_brute.html`](images/dir_brute.html)。

**并发探测与实时打印**：20 线程让 720 个 URL 0.25 秒跑完；命中用
`as_completed` 实时打印（顺序不固定，口径以汇总行为准），每线程独立
`requests.Session` 复用 TCP 连接。

**软 404 降噪是本实验的核心**：先对三个随机路径（如 `/9f3a2b7c1d`）各发一次
请求——都回 200 且长度 100B 就取中位数为基线，之后凡「同状态码且长度
±10B 内」丢弃：

```python
def hits_soft404(r, baseline):
    if baseline is None:
        return False
    # baseline = (状态码, 中心长度, 窗口半宽)
    return r.status_code == baseline[0] and abs(len(r.content) - baseline[1]) <= baseline[2]
```

实测：关闭降噪 72 个词全部「命中」（61 个误报），开启后只剩 11 条真实路径；
局限——长度窗口是启发式：采样波动大（动态页面）时自动加宽窗口兜底，
仍可用 `--tol` 调整灵敏度。

**递归一层**：命中 301/302（或 200 无扩展名）即判定为目录；不跟随跳转，301
响应里的 Location 头（指示跳转地址的字段）就是目录信号。对该目录再跑字典，
补上 `/admin/panel`、`/api/status`；只做一层：请求量 = 字典 ×（1 + 目录数），
靶站已是 720 次。

**靶站的设计**：一份 `configs/lab_site_paths.json` 同时供靶站与断言读取；顶层
未知返回 200（软 404 陷阱）、目录内未知返回真 404、`robots.txt` 泄露 `/secret/`。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **apply 报「靶站 4 秒内未就绪」**：8010 被占用。`lsof -i :8010` 找占用者，
  或 `LAB_PORT=8011 ./dir_brute.sh` 换端口重跑。
- **真实站点命中多到离谱**：多半是软 404 或动态页面。看有没有「软 404 基线」
  行，用 `--no-filter` 跑一遍对比误报规模，或调 `--tol` 放宽窗口。
- **漏报预期的路径**：状态码不在白名单（如 500）或字典缺词——`-s` 扩白名单、`-w` 换字典。
- **递归后请求量暴涨**：每个目录命中都再跑一遍整本字典；真实目标先降线程
  （`-t 5`）再加 `-r`，限速可参考实验 01 的限速器。

深入问答：

- **Q: 软 404 还有别的识别方法吗？** A: 把随机词响应作为模板做字节级或相似度
  对比、统计整批响应长度众数、或用 ffuf 的 `--ac` 自动校准；基线法最小但够用。
- **Q: robots.txt 怎么成了情报源？** A: Disallow 列出的是站主想藏的路径，
  等于给对手一份目录提纲——本靶站的 `/secret/` 就是从这里泄露的。
- **Q: 对真实目标可以开 20 线程吗？** A: 不要——高并发等于开灯行动：WAF
  （Web 应用防火墙）拦截、日志留痕，还可能打崩小站；授权测试先降到个位数线程。
- **Q: DVWA 对照里 /security.php 为什么会被当成软 404？** A: 未登录时它和
  未知路径的响应完全同形（302 → login.php、空体）——降噪按「同状态同长度即
  丢弃」处理，属设计盲区；`--no-filter` 复核可见，过滤与漏报是一枚硬币。
