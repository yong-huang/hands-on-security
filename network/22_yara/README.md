# 22 · YARA 规则与恶意样本扫描器：三条规则、白名单与万级性能

> YARA（把「恶意样本长什么样」写成规则的描述语言，安全行业的通用工具）
> 让检测规则不再写死在代码里。本实验写三条规则抓三种形状——行业标准测试
> 串、多串组合、正则端点——扫 10 个自造样本：3/3 检出、零误报；EICAR
> （反病毒行业标准的无害测试文件）必中；10000 个文件全量扫描亚秒级。
> 样本全部自造，不需要真病毒。

## Background

蓝队（安全对抗中的防守方）三路（实验 19 日志、20 规则匹配流量、21 统计
心跳）之后，文件层还缺一块：怎么把「恶意样本长什么样」从经验变成
**可执行的检测**？YARA 把经验写成模式的 DSL（领域特定语言）；反病毒
引擎、EDR（端点检测与响应平台）、在线沙箱都用它做样本初筛。

和实验 20 的 Suricata（网络流量的模式匹配引擎）规则同源——都是
「模式 + 条件」的判定引擎，只是检查对象从网络流量换成了文件字节。

## What

一句话定义：**YARA 规则 = strings（找什么） + condition（什么条件下算
命中）**；扫描器 = 遍历 × 匹配 × 报告。

心智模型：通缉令——画像（strings）加一条「见到符合画像的就上报」的
规则（condition）。画像越准，误报越少。

失效边界：规则只能抓「写进画像的形状」——加壳（重新打包、改变文件
字节）、混淆（改写成难读的等价形态）会让人眼可见的静态特征失效；
YARA 是初筛器，不是判决器。

三条规则各抓一种形状（本实验样本）：

| 规则 | 形状 | 命中样本 |
|:---|:---|:---|
| EICAR_Test_File | 精确文本串 | sample-01（标准测试件） |
| Suspicious_Download_And_Execute | 多串组合（下载 × 执行） | sample-02 |
| Hardcoded_IP_Endpoint | 正则（IP + .php 端点） | sample-03 |

## When to Use

典型场景：事件响应的样本初筛（一堆文件先过规则再人工）；把威胁情报
（外部收集：攻击者基础设施与手法）里的 IOC（失陷指标：恶意域名、IP、
文件哈希）落成规则分发；CI/CD 里扫描构建产物是否夹带已知特征。

何时不用：一两个文件直接 `strings`（抽文件里可打印字符串的命令行工具，
与 YARA 规则的 strings 段不是一回事）看就行；加壳样本要交给动态沙箱
（隔离环境里实际运行、观察行为的工具，实验 26）；规则维护本身是长期
工程，别写一堆没人复核的 YARA。

| 做法 | 机制 | 什么时候选它 |
|:---|:---|:---|
| 手写规则（本实验） | 三类形状逐条验证 | 看清规则语言的最小闭环 |
| 社区规则集 | 现成 IOC 规则库 | 覆盖已知家族与情报 |
| 动态沙箱 | 运行行为观察 | 对抗加壳与混淆 |

## Quick Start

前置：`pip3 install yara-python`（wheel 自带引擎，无需单独装 yara）。
不需要 root、不需要网络。

```bash
cd network/22_yara
./yara_lab.sh            # 生成样本 → 三规扫描 → EICAR → 白名单 → 性能（约 10 秒）
./yara_lab.sh apply      # 只生成 10 个样本与白名单示例
./yara_lab.sh observe    # 只跑四步验收
./yara_lab.sh clean      # 只清 artifacts
```

诚实预期（新手第一个失败点）：① 规则**先过编译**——语法错误在加载时
就报（报错行号指到规则文件），别等扫完才发现；② EICAR 是给检测链路
看的测试串——本实验写入无碍，受管终端上被 EDR 拦下也属预期；③ 性能线
30 秒极宽松（实测 0.4 秒），别先想着上并发。

## How It Works

![扫描流水线](images/yara_scan.svg)

> 怎么看：样本目录与白名单两个输入进遍历器（白名单在遍历期就跳过），
> 其余文件逐个送进三条规则，命中带规则名/偏移/命中串进报告。

> 🌐 **交互版**：本地打开 [`images/yara_scan.html`](images/yara_scan.html)。

**规则的解剖**：strings 三种形态——文本（如 `"curl -s"`，`nocase` 表示
忽略大小写）、十六进制（`{ 6A 40 ?? }`）、正则（`/re/`）；condition 做
逻辑组合。读法：`1 of ($dl*) and 1 of ($x*)`——两组都要命中，单独看无罪，
合起来才可疑。

**对齐验收的「带答案考试」**：3 个样本各埋一种形状，7 个正常文件故意
放在同一目录当干扰；检出必须恰好 3/3、误报必须恰好 0——报告里每一条
命中都带命中串与字节偏移，可直接复核。

**白名单降噪发生在遍历期**：命中路径子串的文件**根本不会进匹配引擎**
（比「扫完再过滤」省一次匹配），跳过数单独计数。纪律：白名单只收
「已确认无害」——EICAR 是标准测试件才配进队列。

**性能与 PE 特征**：单文件毫秒级、万级 0.4 秒，杠杆在规则质量：字符串
越精准、条件越收紧，越快也越准。规则同样能检查 PE（Windows 可执行
文件格式）结构——`uint16(0) == 0x5A4D` 读文件头两个字节查「MZ」标志，
写法与文本规则相同（strings + condition）。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **规则编译报错**：常见于缺 condition、引号不配对、正则分隔符没闭合——
  报错带行号，直接改规则文件。
- **误报突然变多**：新增规则条件太宽（如只写 `$s = "curl"`）——收紧成
  组合条件，或给串加 `nocase` 之外的边界（前后缀）。
- **EICAR 被系统顺手处理**：它是给杀软看的测试串——本实验观测写入无碍；
  受管终端上被 EDR 拦下属预期，正说明检测链路活着。
- **扫描一个目录全是命中**：规则太泛 + 没配白名单——先收规则，再把
  「已确认无害」的路径进白名单，别反过来。

深入问答：

- **Q: YARA 和 ClamAV（一款开源杀毒引擎）的特征库什么关系？** A: 同类
  思路的不同形态——这里的「签名」指样本特征码（不是密码学签名），
  ClamAV 用自家私有格式，YARA 通用可移植（EDR/沙箱/VirusTotal——多引
  擎在线查毒网站——都支持）。
- **Q: 加壳/混淆样本怎么办？** A: 静态特征会失效——转动态行为（实验 26）
  与内存扫描；YARA 也支持扫原始内存镜像。
- **Q: 为什么组合规则比单串规则好？** A: 单串命中的先验太弱（curl 之
  类词到处都是）；「下载 × 执行」的组合把误报率压下来——这也是 YARA
  规则设计的一课：**形状要小，逻辑要严**。
