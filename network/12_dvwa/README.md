# 12 · DVWA 靶场与渗透工作台：compose 起栈、CSRF token 与改包重放

> DVWA（Damn Vulnerable Web Application，故意做坏的练习靶站）是 Web 渗透
> 的经典沙袋——实验 13-18 的 SQL 注入、XSS、上传、爆破全部打在它身上。
> 本实验把整套工作台搭起来：双容器栈、一键建库、自动登录切档，并用 curl
> 复刻「拦截 → 改包 → 重放」（把请求扣在途中、改一个字段、再原样发一次）。
> 仅本机实验，勿对未授权目标使用。

## Background

想练渗透却没有目标：打真实系统违法，拿生产环境试手更是灾难。靶场因此
出现——一个「漏洞是故意留的、可以随便打、随时重建」的练习环境。

DVWA 是其中最经典的一款：一个 PHP 小站，覆盖 SQL 注入、XSS、文件包含、
命令注入等十余个漏洞模块，每个模块有 low / medium / high / impossible
四档实现——同一漏洞从「完全不设防」到「正确修复」逐级演示，是「从打到
防」一体化的标准教具。

后续实验需要反复起停这个靶站，所以本实验的重点除了「跑起来」，还有
「工程化」：容器化、一键化、可重建。

## What

一句话定义：渗透工作台是**靶场（可攻击的目标）+ 工具（浏览器、Burp（抓包
代理：把 HTTP 请求拦下来查看与修改的工具）、curl）+ 编排（compose——
Docker Compose，用一份 YAML 声明并起停多容器应用的工具——与自动化脚本）**
的三件套。

心智模型：靶场像拳击馆的沙袋——练重拳先要有挨打的沙袋，而且沙袋的
「硬度」可调（DVWA 的安全等级就是那排档位旋钮）。失效边界：在靶场赢
一百次不等于真实系统安全——真实世界没有 low 档，但也没有「允许你打」
的授权。

四个安全等级的含义（后续实验会逐档对比）：

| 档位 | 含义 | 用途 |
|:---|:---|:---|
| low | 完全不设防 | 学漏洞原理、看清利用链 |
| medium | 基础过滤（可绕过） | 学「不充分的防御长什么样」 |
| high | 较严过滤 | 学绕过思路的极限在哪 |
| impossible | 正确实现 | 学修复范式 |

## When to Use

典型场景：学习 OWASP Top 10（Web 应用十大风险榜单，在可攻击环境里逐类
复现）；给检测工具（实验 19-21 的日志审计与 IDS（入侵检测系统））喂真实
攻击流量；练习写渗透报告。

何时不用：别把 DVWA 暴露到公网或办公网——它真的漏洞百出，暴露即被
接管；教学之外也无需自建靶场，Juice Shop 等同类靶场按口味任选。

| 方案 | 机制 | 什么时候选它 |
|:---|:---|:---|
| DVWA（本实验） | PHP 小站，四档对比 | 经典、轻量、档位教学清晰 |
| OWASP Juice Shop | Node 现代 SPA（单页应用） | 想练现代前后端漏洞 |
| 自建漏洞应用 | 自己写故意做坏的功能 | 定制场景、深度理解 |

## Quick Start

前置：Docker Desktop 运行中；脚本自带「离线搭栈」能力（见 How It Works）。

```bash
cd network/12_dvwa
./dvwa.sh               # 起栈 → 建库 → 三项验收 → 拆除（首次约 2-4 分钟）
./dvwa.sh apply         # 只起栈并初始化（栈留在运行状态供后续实验）
./dvwa.sh observe       # 只跑三项验收（探活/登录切档/改包重放）
./dvwa.sh status        # 看容器状态
./dvwa.sh clean         # 拆除栈与数据卷（源码保留）
```

冷启动的真实输出（节选）：

```text
  ✅ DVWA 源码已存在：artifacts/dvwa（复用；删掉该目录可重新下载）
  ✅ config.inc.php 已存在（复用）
... # 块首「环境检查与靶场栈启动」段头与「构建并启动」段头、compose 构建/创建容器约 50 行输出省略（段内空行从略，下同）
  ✅ 入口就绪：http://localhost:8612/login.php
... # 「初始化数据库」段头省略
  ✅ 数据库已建好（dvwa 库 4 张表，含 users/guestbook）
... # 「验收一」段头省略
  curl -s -o /dev/null -w "%{http_code}" http://localhost:8612/login.php
  → 200
  ✅ login.php 返回 200
... # 「验收二」段头省略
  ✅ 登录成功（admin / password）
  ✅ 安全等级已切换为 low（后续实验 13-18 的默认档位）
... # 「验收三」段头与两行说明省略
  ✅ 重放成功：等级被改成 medium —— 服务器直接信任客户端提交（DVWA 的设计）
  ✅ 已复位回 low
... # Burp 提示行与 clean 段（拆除输出及其 ✅）省略
```

诚实预期（新手第一个失败点）：首次构建要装 PHP 扩展、初始化 MySQL——
脚本提示约 1-3 分钟，网络受限时更久（本机实测 2-4 分钟属正常）；重复运行
秒级。另一个「看起来失败」的点：本机没装 Burp 时最后一步会提示——验收用
的是 curl 复刻版，Burp 是给人看的手工版（步骤见下），两者工作流一致。

## How It Works

![DVWA 渗透工作台](images/dvwa.svg)

> 怎么看：左侧宿主机上，浏览器走 Burp（可选）或直连进 web 容器；
> 右侧 compose 栈里 web（php82 内置服务器）连 db（mysql:8.0），
> 源码与数据各自挂卷——拆栈不丢源码，重建秒级起。

> 🌐 **交互版**：本地打开 [`images/dvwa.html`](images/dvwa.html)。

**栈为什么长这样**：web 用 php82 的**内置服务器**（够跑 DVWA，还省掉一层
Apache 配置）；db 用本机已有的 mysql:8.0；`depends_on + healthcheck`
保证 web 等数据库健康后再起，避免首启竞态；源码用卷挂载——改代码、看
代码不用重建镜像。

**一键建库与 CSRF token**：DVWA 1.10+ 的每个表单（建库/登录/切档）都带
一次性 token（CSRF＝跨站请求伪造；token 是服务器嵌进表单的随机串）。脚本
`post_form` 先 GET 取 token 再提交——自动化渗透处理 token 的最小样本。

**改包重放**：拦截 → 改一个字段（low→medium）→ 重放。服务器照单全收
——「当前安全等级」在 DVWA 里就是客户端提交的状态。Burp 手工版：装好后
保持默认 Proxy 端口 **8080** 即可（靶站已避开 8080，选 8612），浏览器
代理指向它，开 Intercept 重复登录即可。

**离线搭建实录**（网络封锁下）：Docker Hub 断流、GitHub 直连 000、Debian
源超时——对策：源码走加速代理下 tarball、web 镜像从本地 alpine 起底
（apk 装 php82）、db 用本机已有 mysql:8.0、apk 加缓存挂载与重试。这是
这台机器真实跑通的流程。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **8612 被占用**：`lsof -i :8612` 查占用者，或 `DVWA_PORT=8613 ./dvwa.sh`。
- **登录失败但页面正常**：多半是数据库没初始化——先跑 `./dvwa.sh apply`
  让 setup.php 建库（脚本已自动化）。
- **表单提交没反应**：CSRF token 缺失或复用——token 是一次性的，每个
  表单提交前都要重新 GET 页面（`post_form` 已封装）。
- **apk 报 IO error**：本机网络抖动——Dockerfile 内已带缓存挂载与重试；
  仍失败时 `docker builder prune -f` 后重跑。

深入问答：

- **Q: 为什么 web 用内置服务器而不是 Apache？** A: DVWA 是纯 PHP 站点，
  内置服务器零配置即可跑；实验 10 已完整演示自建 CA 与 TLS 那一层，这里
  不重复。追求「像生产」可换 php:apache（注释见 `configs/web.Dockerfile`）。
- **Q: 容器删了数据还在吗？** A: `clean` 连数据卷一起删（靶场就该可重置）；
  源码在宿主机 `artifacts/dvwa`，不受影响。
- **Q: Burp 和 curl 两条路学哪个？** A: 都学——Burp 是手工渗透的显微镜
  （看清每个请求），curl 是自动化的起点（把手工动作变成脚本）。
- **Q: 四档安全等级怎么切？** A: 登录后 security.php 下拉框即可；脚本已把
  默认档位设为 low（`default_security_level`），后续实验逐档对比攻防。
