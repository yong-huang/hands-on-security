# 26 · 恶意行为监控沙箱：进程树 / 文件变更 / 网络外联三路画像

> 实验 23 做的是「事后取证」（翻日志找脚印）；这一课做「事中监控」：一个
> 模拟勒索剧本的样本（批量 XOR「加密」+ 改名 .locked + 勒索说明 + 向 C2
> 发 3 次 HTTP 心跳）在一次性容器沙箱里跑，三台摄像机同时开机——进程树
> （psutil 轮询「谁拉起谁」）、文件变更（watchdog / inotify 记录创建与
> 删除）、网络外联（连接快照 + 内置 C2 陷阱收心跳）——7 条规则加权评分
> **115 → 高度疑似恶意**；同一套检测器对纯计算样本 **0 告警**。报告给出
> 时间线、证据与结论，脚本对报告做验收断言。

## Background

实验 23 是事后取证：翻文件 mtime 拼时间线。但更好的防线是「事中」——
样本还在跑，行为已经落进监控窗口。这就是 EDR（Endpoint Detection and
Response：终端检测与响应）的核心：不停机、边跑边看。

本实验把 EDR 的三件套（进程 / 文件 / 网络）缩成 250 行可读代码，并立下
和检出同等重要的纪律：**不冤枉好人**。

## What

一句话定义：**行为监控 = 用「它做了什么」识别恶意**，而不是「它长什么样」
（后者是实验 22 的 YARA 静态特征）。

心智模型：沙箱像一间带三台摄像机的审讯室——让嫌疑人（样本）自由行动，
摄像机分别拍「和谁互动」（进程）、「动过什么物件」（文件）、「给谁打过
电话」（网络）；分析师（规则引擎）看完录像，给行为定性。

失效边界：规则引擎只认「写进规则里的行为」——反沙箱样本装死、慢速潜伏、
容器逃逸都超出本节；且行为监控成本高（得真把它跑起来），初筛仍靠静态。

| 摄像机 | 盯什么 | 本实验逮到的 |
|:---|:---|:---|
| 进程树（psutil） | 谁拉起谁 | 样本树下 2 个子进程（加密 worker / 心跳 worker） |
| 文件（watchdog） | 创建 / 删除 / 修改 | 5 个 .locked 落盘 + 5 个原件删除 + 勒索说明 |
| 网络（快照 + 陷阱） | 远端端点 / 频率 | 3 次 /beacon 心跳（127.0.0.1:9099） |

## When to Use

典型场景：样本初筛的第二关（YARA 命中后做行为验证）；理解 EDR / 云沙箱
产品的核心原理；IR（Incident Response：应急响应）现场「目标还活着」时
的事中布控（对比实验 23 的事后）。

何时不用：只想要「是不是恶意」的一句话时，静态特征往往更快；纯网络攻击
（无落地文件）要换网络侧的采样点，本节三台摄像机拍不到。

| 手段 | 看什么 | 什么时候选它 |
|:---|:---|:---|
| YARA 静态（实验 22） | 字节特征 / 字符串 | 秒级初筛 |
| 行为监控（本节） | 运行时动作 | 验证意图（要真跑样本） |
| 人工逆向（实验 24） | 指令级逻辑 | 疑难样本兜底 |

python3-psutil + python3-watchdog）；宿主机只需标准库。

```bash
cd network/26_sandbox
./sandbox_lab.sh            # 恶意 + 良性各跑一遍 → 检出与零误报（约 20 秒）
./sandbox_lab.sh apply      # 只构建沙箱镜像
./sandbox_lab.sh observe    # 只跑两趟监控与报告核验
./sandbox_lab.sh clean      # 清理 artifacts（镜像保留）
```

诚实预期（新手第一个失败点）：① 报告里的相对时间是**真实监控时间**——
本文档展示层做了 T+Xs 归一化（是它换来「两跑逐字一致」）；② 良性零误报
不是白送的：检测器先过准入线（同 23 的纪律）；③ 三路采集是 EDR 的最小
内核——真产品还差内核驱动、离线队列与反对抗。

## How It Works

![沙箱解剖：三路采集如何逮住勒索剧本](images/sandbox.svg)

> 怎么看：左起「沙箱脚本」把样本放进一次性容器；容器内样本的三类行为
> 分别被进程 / 文件 / 网络三台摄像机拍下，汇入规则评分引擎；引擎产出的
> 画像报告钻出容器落在宿主，由脚本做验收断言。

> 🌐 **交互版**：本地打开 [`images/sandbox.html`](images/sandbox.html)。

**三路为什么要分开**：单路都有盲区——进程树看不出「加密」（python 进程
也会算数学题）；文件看不出「心跳」；网络看不出「删除」。三路交叉才拼出
「批量加密 + 定时外联」这个勒索画像。

**C2 陷阱是设计出来的证据**：被动轮询连接会漏（心跳间隔稍长就抓不到），
于是在沙箱里架一个诱饵 HTTP 服务——样本「必然」联系 127.0.0.1:9099，
每次心跳的次数、路径、时间都落袋，一个都跑不掉。

**评分不是重点，准入线才是**：7 条规则按危害加权（加密 +30 / 心跳 +25 /
勒索说明 +15……），≥60 判高度疑似；真正保证质量的是**良性样本必须 0 分**
——检测器先证明不冤枉人，再谈抓坏人（验收两半同等硬）。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **两跑对不上，全是时间**：监控输出天然带相对时间——展示层用 T+Xs
  归一化（报告文件保留原始值）；时间线顺序另用 0.1s 桶 + 规则序钉死。
- **桶内乱序**：同一批文件事件的毫秒先后随机——排序键必须带稳定
  tie-break（开发时被 ③ 核验抓过一次现行）。
- **psutil 改名坑**：`net_connections()` 是 5.9.8+ 的新名，Ubuntu 22.04
  （代号 jammy）自带的 5.9.0 还叫 `connections()`——要写兼容分支。
- **改了文件、容器里没变**：macOS 挂载层有读缓存，改完立刻跑容器可能
  读到旧版（几秒后自愈）——开发期排错先怀疑它。

深入问答：

- **Q: 为什么用容器而不是虚拟机？** A: 本节隔离级别（--rm 用完即弃 +
  只读挂载）已够，还快；真沙箱另要网络全断、内核级隔离与反对抗。
- **Q: 样本识破沙箱装死怎么办？** A: 反沙箱对抗是独立战场——行为监控
  抓不到「没有的行为」，这也是静态特征仍不可替代的原因。
- **Q: 评分表怎么调？** A: 加权与阈值靠试验平衡：太敏感误报、太钝漏检；
  准入线（良性 0 告警）就是调参时的护栏。
