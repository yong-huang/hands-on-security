# 23 · 应急响应靶场演练：五处后门、五路取证与时间线还原

> IR（Incident Response：应急响应——对安全事件的分诊、取证与处置）的
> 黄金前几小时怎么过：先保全、再取证、后动作。本实验用 Docker 预演一个
> 「被入侵的 ubuntu」——预埋五处后门：cron 反弹（计划任务里让机器主动
> 回连攻击者）、UID 0 隐蔽账号（多一个 root 级用户）、ssh 公钥、隐藏
> SUID（带 setuid 位、以属主权限运行的提权文件）、history 自证。只读
> 排查脚本一次拿全 5/5；基线镜像对照 0 误报；产出带证据路径与时间线的
> IR 报告。全部文件级预埋，安全可控。

## Background

前四课（19 日志、20 Suricata、21 Zeek、22 YARA）都在练「检测」——那检
测到之后呢？IR 接手，做三件事：分诊（哪些机器中招、攻击到了哪一步）、
取证（证据在哪、时间怎么走）、处置（清什么、改什么、还要查多远）。

本实验在 Docker 里复刻「案发现场」：镜像构建期预埋五处后门，排查脚本
对着导出的只读快照逐项取证——练的是**排查路径与报告写作**这两样最
容易在真实事件里手忙脚乱的东西。

## What

一句话定义：**入侵排查 = 按「持久化面清单」逐项取证**（计划任务 / 账号 /
SSH 公钥 / SUID / 命令历史——攻击者要长期驻留，就绕不开这几个地方），
再把发现按 mtime（文件最后修改时间）串成时间线。

心智模型：查房——拿固定清单走一遍房间（门锁换没换、有没有多住人、钥匙
挂在谁手上），再按监控时间戳还原「谁什么时候进了哪间」。

失效边界：静态快照看不到正在运行的东西（进程、内存马——只驻留内存、
没有磁盘文件的恶意程序、网络连接）——真实 IR 要先抓易失数据再做镜像；
本实验练的是静态取证这一半。

| 检查面 | 找什么 | 预埋样本 |
|:---|:---|:---|
| 计划任务 | 外连命令（/dev/tcp、nc -e） | /etc/cron.d/system-update |
| 账号 | UID 0 的「第二个 root」 | support:x:0:0:… |
| SSH 公钥 | 陌生 authorized_keys | /root/.ssh/authorized_keys |
| SUID | 非白名单的 setuid 文件 | /usr/local/bin/.sysmon |
| 命令历史 | 操作自证 | /root/.bash_history |

## When to Use

典型场景：值守介入的第一步（照清单跑一遍再深入）；事后复盘（拿到快照
出报告）；定期巡检（把基线机当对照组跑零误报）。

何时不用：单台个人机器直接人眼看就行；进程级威胁要配内存取证与动态监控
（实验 26）。排查脚本的价值在「机器多、要复盘、要留证据」的时候。

| 做法 | 机制 | 什么时候选它 |
|:---|:---|:---|
| 手工翻（少量机器） | ls/cat/ps 逐项看 | 一台两台的现场 |
| 自写排查脚本（本实验） | 清单化取证 + 评分 | 批量、复盘、留证据 |
| 专业 IR 平台 | 主机 Agent + 编排 | 规模化事件响应 |

## Quick Start

前置：Docker（本机无 `ubuntu:22.04` 时自动经 daocloud 镜像拉取）；仅
Python 3 标准库。保证 0 误报的前提下约 30 秒。

```bash
cd network/23_ir_drill
./ir_lab.sh            # 建靶机 → 导快照 → 五路排查 → 基线对照 → 报告（约 30 秒）
./ir_lab.sh apply      # 只构建靶机镜像并导出「靶机 + 干净基线」快照
./ir_lab.sh observe    # 只跑排查、基线对照与报告核验
./ir_lab.sh clean      # 只删演练容器与快照（镜像保留）
```

诚实预期（新手第一个失败点）：① 时间线统一用 **UTC**——容器与宿主时区
差 8 小时，混用会让「发现时间」错位（实测踩过）；② macOS 的 tar 以普通
用户解包会**剥掉 SUID 位**——本脚本用 python tarfile 导出；③ 基线对照
不是可选项：没有 0 误报的准入线，5/5 不能算数。

## How It Works

![应急响应排查流水线](images/ir_drill.svg)

> 怎么看：两个靶机（预埋/干净）各导出一份只读快照；排查脚本五路取证，
> 评分并用 mtime 还原时间线，输出带证据路径的 IR 报告；最右是处置闭环。

> 🌐 **交互版**：本地打开 [`images/ir_drill.html`](images/ir_drill.html)。

**五路取证的落点**：cron 找外连命令、账号找 UID 0、key 找陌生公钥、
SUID 找非白名单、history 找自证。每处都留「路径 + 片段 + mtime」三件套
——证据格式统一，报告才能自动生成。

**SUID 白名单靠实测**：干净基线镜像里标准 SUID 有 8 个
（chfn/chsh/gpasswd/mount/newgrp/passwd/su/umount）——白名单从基线实测
来，不靠记忆猜；预埋的 `.sysmon` 不在白名单里，一抓一个准。

**评分与时间线**：严重 40 / 高 25 / 中 15，本例累计 120 → 高度疑似失陷；
报告第三节按 mtime 排序，还原出 02:41（种 cron）→ 03:05（加账号）→
03:22（留钥匙）→ 03:40（提权后门）→ 04:02（history 自证）的入侵剧本。

**处置闭环**：报告以行动项收尾（清后门、改密、横向巡检）——和实验 18
的渗透报告首尾呼应：攻的产出是证据链，守的产出也是。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **发现时间错位 8 小时**：容器是 UTC、宿主是北京时区——取证时间统一
  记录 UTC 并标注（本实验报告开头就写「时间线时区：UTC」）。
- **SUID 清单全空**：macOS tar 剥位——用 python tarfile 解包（脚本里已
  这样处理，Python 保持模式位）。
- **基线出了误报**：SUID 白名单没从基线实测收集——标准 su/passwd 会被
  当成后门报出来；白名单与规则一样，要靠数据。
- **快照被改坏**：分析只在只读快照上作业，永不改原件——可复算性是取证
  的底线。

深入问答：

- **Q: 为什么后门只做「文件级」预埋？** A: 演练要安全可控——不需要真的
  sshd（SSH 服务端进程）/cron 进程；文件与 mtime 就是取证对象。真实环境再加进程、网络、
  内存三路（易失性顺序：内存 → 网络 → 磁盘）。
- **Q: 时间线为什么按 mtime？** A: mtime 是证据自带的时钟；但它**可以
  被改**（本实验就是自己 `touch -d` 伪造的）——所以时间线必须与系统日志
  交叉验证，孤证不算。
- **Q: 检出之后第一步做什么？** A: 不是删文件——是先**固定证据**（归档
  并哈希），再处置；顺序错了，证据就没了。
