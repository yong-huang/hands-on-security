# 09 · RSA 原理与混合加密：模运算、OAEP 与信封实验

> 公钥密码（加密与解密用不同钥匙）解决了「素未谋面怎么交换钥匙」的死结，
> 但 RSA 又慢、单次能装的数据又少。本实验先用纯 Python 复算教材经典样例
> （p=61、q=53 → 私钥 d=2753），再看 OAEP 填充补上教材版的漏洞，最后用
> AES-GCM + RSA-OAEP 给 1MB 文件做「信封加密」。示例密钥仅限本地教学。

## Background

对称加密有个先有鸡还是先有蛋的问题：双方得先共享同一把钥匙，可这条
「安全的送钥匙通道」本身又需要加密。1949 年香农证明「一次性密码本」
（密钥与消息等长、只用一次）理论不可破——顺手点破另一面：安全分发
密钥绕不开，双方终究要先拿到同一份密钥。

1977 年 RSA 用「单向门」破局：两个大素数相乘容易、从乘积倒推极难——由
此做出一对数学关联的钥匙，公钥随便发、私钥自己留。但工程上它又慢、单次
只能加密一小段；实际系统因此不「用 RSA 加密文件」，而是混合加密：RSA 送
钥匙、AES 搬数据——HTTPS、PGP、消息应用都这么干。

## What

一句话定义：混合加密是**用非对称加密（即开头的公钥密码：加解密用不同
钥匙）分发/封装一把对称密钥，再用对称加密搬运数据**的组合方案。

心智模型：保险箱 + 搬运工——RSA 是一只贵重的小保险箱，只用来把「钥匙」
递给对方；AES 是那位能一车车搬货的搬运工。失效边界：安全性完全依赖
「数学难题 + 实现规范」两条腿——参数或填充写错（如本题的教材版），
保险箱就是一个没锁的铁盒。

三代做法对照：

| 做法 | 机制 | 结论 |
|:---|:---|:---|
| 教材版 RSA | c=m^e mod n，无填充 | 只用于学原理，确定性 + 同态性可被利用 |
| RSA-OAEP | 随机填充后再模幂 | 真实 RSA 加密的标准姿势 |
| AES-GCM + 信封 | RSA 封装密钥、AES 搬数据 | 本实验的混合加密全流程 |

两个弱点先记下：**确定性**（同文同密，可被比对猜出）与**同态性**（密文
相乘 = 明文相乘，E(2)·E(3)=E(6)）——它们是「教材版不能上线」的原因。

## When to Use

典型场景：理解 HTTPS 握手、签名、证书链从哪来；实现文件/消息加密时做对
选型；复算教材例题把「模幂、欧拉函数、模逆」从公式变成手感。

何时不用：不要手写 RSA 上线（Bleichenbacher 之类攻击专门咬实现细节）；
大文件不要直接 RSA（2048 位密钥装不下）；需要加密就直接用成熟库的
AEAD（带认证的加密，如本实验的 AES-GCM）+ 密钥协商协议（双方在线协商出
共享密钥的协议）。

| 方案 | 机制 | 什么时候选它 |
|:---|:---|:---|
| RSA-OAEP + AES-GCM（本实验） | 信封结构 | 学习原理、小规模自用工具 |
| ECIES（基于椭圆曲线密码的信封方案） | 用椭圆曲线协商密钥 | 同样的活，密钥更短更现代 |
| 纯对称 + 预共享密钥 | 无公钥环节 | 设备间已能安全配置同一密钥 |

## Quick Start

前置：`pip3 install cryptography`（仓库根 `bash scripts/load_resources.sh pip` 可一键补依赖）。

```bash
cd network/09_rsa_hybrid
./rsa_lab.sh              # 造信封 → 教材版复算 → OAEP → 解封/篡改（约 3 秒）
```

## How It Works

![混合加密信封](images/rsa_lab.svg)

> 怎么看：上排是数据通道（AES 加密 1MB），下排是钥匙通道（RSA 封装
> 会话密钥），两段在信封文件汇合，解密端分别解封、解密，最后逐字节核对。

> 🌐 **交互版**：本地打开 [`images/rsa_lab.html`](images/rsa_lab.html)。

**单向门的数学**：公钥 (e, n) 与私钥 d 满足 e·d ≡ 1 (mod φ(n))——d 是 e
的模逆元。φ(n) 叫欧拉函数（与 n 互质、小于 n 的整数个数；素数为
(p-1)(q-1)），扩展欧几里得求 gcd 时顺带解出。反求 d 需要 φ(n)，问题
推回「分解 n」——安全性所系。

**教材版为什么不能上线**：输出里两条 `[弱点]` 是照妖镜——确定性（同文
同密，可被比对猜出）与同态性（密文相乘 = 明文相乘，E(2)·E(3)=E(6)）。
真实 RSA 靠 OAEP 随机填充补上这两刀：加密前把明文和随机数一起哈希混合，
解密时校验——所以同一消息两次密文不同。

**信封格式与两道闸**：`envelope.bin` = 8B 魔术头（固定标识）+ 2B 长度 +
256B 封装密钥 + 12B nonce（一次性随机数）+ 密文段。篡改数据段 → GCM 标签
抛 `InvalidTag`；篡改密钥段 → OAEP 填充校验直接失败。两段各自防拆。

**为什么 1MB 必须走 AES**：RSA-2048 + OAEP 单次上限约 190 字节；把 1MB
切成几千块逐块 RSA 加密既慢又缺乏模式保护——混合加密才是工程正解。

## Pitfalls & Q&A

踩坑清单（现象 → 原因 → 解法）：

- **别手写 `m ** d` 再取模**：大数直接幂会爆内存——模幂运算用 Python
  内建三参 `pow(m, d, n)`。
- **OAEP 参数不一致**：哈希与 MGF1（基于哈希的掩码生成函数，OAEP 内部
  用它摊开随机数）必须在加解密两侧一致（本实验统一 SHA-256），否则解密直接失败。
- **私钥文件别外传**：`artifacts/rsa_key.pem` 是明文私钥；`clean` 会删，
  真实系统私钥要有口令保护与权限控制。
- **篡改演示只改副本**：代码对内存拷贝翻字节，磁盘上的信封保持完好——
  真实场景里记得先备份再研究。

深入问答：

- **Q: 为什么 d 是「模逆」而不是 1/e？** A: 模运算里没有除法，只有逆元：
  e·d 除以 φ(n) 余 1。1/e 是个小数，没法当指数用。
- **Q: 电子签名和加密是同一套钥匙吗？** A: 数学同源、方向相反：加密用
  公钥、解密用私钥；签名用私钥、验签用公钥——本实验只覆盖了加密方向。
- **Q: RSA 会被量子计算机干掉吗？** A: 理论上会（Shor 算法能分解大数），
  所以后量子密码正在标准化；工程上的迁移是漫长过程，但方向明确。
- **Q: 教材版连填充都没有，为什么还教？** A: 它是理解「单向门」的最小
  例子——但记住它的教训：密码学的「数学正确」与「工程安全」之间隔着
  一整套规范（填充、参数、密钥管理）。
